# 图片与视频提示词硬格式

本文件是交付约束，不是可选建议。结构来自《半生》项目：图片采用单段自然语言描述，视频采用六段式和秒级情节。新作品固定如下；原始底版保留原作者实际格式，不为满足新规则改动原文。

## 图片：一个代码块、一段中文、八项固定顺序

必须按顺序填满八项，前七项自然连接，最后一项作为MJ后缀。标题、镜号、说明和操作步骤放代码块外。

| 顺序 | 内部字段 | 必须写明 |
| --- | --- | --- |
| 1 | frame + shot | 数字画幅、横/竖画幅、景别与机位；例如16:9横画幅，平视近景 |
| 2 | subject | 主体身份/年龄阶段、形态/服饰/道具、当下静态瞬间；空镜则为真实物件/自然主体 |
| 3 | composition | 主体位置、前中后景关系、视线或负空间；避免只写“构图高级” |
| 4 | scene | 时代取向的实际空间、季节/天气、固定建筑与环境 |
| 5 | lighting | 主光源及方向、主色与点缀色、明暗关系 |
| 6 | photography | 真人实拍质感的中国古代历史电影剧照、一致的景深/胶片或镜头气质 |
| 7 | material | 当镜可见的2–3项实体材质与克制胶片颗粒；无人空镜不强写皮肤 |
| 8 | parameters | 与画幅一致的MJ参数，只放末尾，不在后面加中文或句号 |

格式骨架仅用于组织，正式交付必须替换所有变量：

```text
[画幅]，[景别与机位]。[主体与静态瞬间]。[构图]。[场景]。[光影色调]。[真人电影拍摄质感]。[材质与颗粒] --ar [比例] --v [已确认版本] --raw --s [数值] --chaos [数值]
```

硬性失败条件：缺项；一个镜头写成多个段落；信息顺序被调换；参数在正文中间；把秒级事件、整句台词、连续动作、推进/环绕/遮挡转场写入静帧；出现未替换变量。年代数字、角色年龄、65mm胶片气质和静止的动作姿态不属于时间轴。

不要在图片代码块内列“主体：/场景：”等分段标签。如用户需要英文MJ版，在中文单段之外另给逐项同序的英文单段；不能省掉中文基准版，除非用户明确要求只要英文。

## 图片代码块外：每镜单列五项设置

用户要求生图参数单独可读。每个图片代码块后紧跟一张表，填写本次建议，不能只写后缀或“沿用上一镜”。固定为五项：

| 设置 | 本镜建议值（示例） |
| --- | --- |
| 画幅 | 16:9 |
| 版本 | V8.2 |
| 风格化程度 | 50 |
| 怪异度 | 0 |
| 多样性（随机性） | 0 |

后三项才是LibTV的三个额外滑杆。风格化对应后缀的`--s`；多样性/随机性对应`--chaos`，不是seed。怪异度是独立设置，不能因为看到某处写50就误认成风格化50。画幅、版本从该镜参数与正文一致提取；数值逐镜决定。

当前本地LibTV观察范围：风格化0–1000、怪异度0–3000、多样性0–100。此为2026-10-08的Style Image V8.2界面记录，不泛化到其他平台。原文后缀与面板冲突时，分别标为“原文参数”和“面板现值”；交付新提示词时仅用一组明确的本次建议。若正文有`--s`/`--stylize`、`--chaos`/`--c`、`--weird`/`--w`，必须与表格一致；不要为补齐表格而猜当前模型不支持的后缀。

在LibTV独立设置界面，用户复制中文正文，按表设置三个滑杆与画幅、版本；末尾MJ后缀供MJ使用，避免在第三方界面同时提交两套相互冲突的配置。不能断言LibTV正文后缀与滑杆谁优先。

## 视频：一个代码块、严格六段、标签固定

每段正文保持一段，段与段之间恰好一个空行；内部时间段用中文分号连接。标签不加粗、不加编号、不改同义词。

```text
主体：[首帧人物/物件、姿态、身份与道具锚点；唯一主动作及稳定项]

场景：[首帧空间与背景；环境动势的方向和幅度；固定结构]

拍摄风格：[总秒数]秒单镜头，真人实拍质感的古代历史电影；[一个主导运镜、焦点和景深]

光影构图：[实际主光源与方向、色调、暗部材质、脸/手/道具位置]

情节：0.00–[第一终点]秒：[动作]；[下一起点]–[下一终点]秒：[动作]；[最后起点]–[总秒数]秒：[可剪尾帧]。声音：[人物说话/旁白/环境音方案]

否定控制：[针对该镜的脸、手、衣服、道具、空间与天气失误]；无字幕、无Logo和水印，不生成BGM。
```

总秒数和时间点必须替换为数字。时间点统一两位小数，起点从0.00开始，后一段起点与前一段终点相等，最后终点与总秒数相等；例如5秒：`0.00–0.50秒`、`0.50–2.50秒`、`2.50–4.00秒`、`4.00–5.00秒`。

“情节与台词”“音频设计”“镜头语言”“负面提示词”等不能替代或追加为段标题。台词、画外音和声音置于情节段的声音说明，主导运镜置于拍摄风格。参数建议、上传说明、匹配图片锚点放在代码块外。

最终匹配版必须绑定镜号和已实际观察的选定图片；未观察图片只能写“待成图校准”的预案，不得声称严格匹配了未见图像。两种状态使用相同六段格式。

## 视频（Seedance 2.5分支）：一个代码块、严格六段、标签固定

仅在走Seedance分支时使用，完整规则见 [seedance-25.md](seedance-25.md)。标签依次为`总控：`、`参考素材：`、`首帧状态：`、`时间轴：`、`声音：`、`否定控制：`，段间恰好一个空行，不得与Kling六段标签混用。

- `总控：`以“[总秒数]秒连续段落，[画幅]”开头，总秒数不超过30且不超过用户界面可选时长，含“真人实拍”与“历史电影”。
- `参考素材：`每条为`@ImageN｜类型｜唯一职责｜保留：…｜不影响：…`，以中文分号连接；无素材写“无”。有角色锚点卡时必须有一条职责为“身份与服装”。
- `时间轴：`从0.00连续到总秒数，两位小数；每段为`起–止秒 S0N：机位…；动作…；对白…；结束…`。
- `声音：`单列，默认不生成BGM；有对白时不写“无声”。
- 预案/最终匹配版的区分同Kling。

## 交付前检查表

1. 当前镜号是否有完整图片八项，或完整视频六段？
2. 代码块数量与镜数对应，代码块外的解释没有混入提示词吗？
3. 图片是否单段、顺序正确、只有静态瞬间、参数在尾部且画幅一致？
4. 视频平台是否明确；Kling/Seedance标签是否逐字正确、顺序固定、恰好六段，声音是否在情节内？
5. 时间轴是否两位小数、从0连续至T，正文/建议/设置是否一致？
6. 最终版是否看过图片，首帧锚点是否都来自该图？没有图时是否明确为预案？
7. 道具、光线、表演与动作能否执行？无人镜头没有强行写脸和口型吗？
8. 每条图片提示词后是否有完整五项设置表，三个额外数值是否具体、同正文/后缀一致，且没有冒充来源的实际生成参数？

第1–6项与第8项是格式与阶段门槛，第7项是语义检查。结构脚本不能证明历史考据、人物一致性或实际生成效果。

## 可运行的格式门槛

用scripts/check_prompts.py把分字段草稿渲染成固定格式，可同时验证画幅、字段完整性、六段标签、时间轴与实际看图门槛。它不联网、不生成素材、不修改底版，只读指定JSON文件并可输出Markdown。

草稿JSON使用UTF-8：顶层`stage`为`images`、`videos`或`both`，`shots`为镜头列表。每镜有唯一`id`。图片对象字段为`frame`、`shot`、`subject`、`composition`、`scene`、`lighting`、`photography`、`material`、`parameters`。有图片的镜头必须另含与`image`同级的`image_settings`，恰有三个整数键`stylize`、`weird`、`chaos`，例如`{"stylize":50,"weird":0,"chaos":0}`；脚本从`--ar`与`--v`读取画幅和版本，一起生成五行设置表。视频对象字段为`status`（`provisional`/`final`）、`image_id`、`image_observed`、`duration`、`主体`、`场景`、`拍摄风格`、`光影构图`、`情节`（start/end/action的列表）、`声音`、`否定控制`。start/end为两位小数字符串。视频对象可加`platform`：缺省或`"kling"`按上述Kling字段校验（旧草稿不改即可通过）；`"seedance"`时字段为`platform`、`status`、`image_observed`、`duration`、`aspect`、`总控`、`参考素材`（tag/type/job/keep/avoid对象列表，可为空）、`首帧状态`、`时间轴`（start/end/shot/camera/action/dialogue/end_state列表）、`声音`、`否定控制`；顶层可加`"role_anchor": true`，要求每个Seedance段有“身份与服装”参考。

```text
python scripts/check_prompts.py --input 本次草稿.json --render 本次提示词.md
```

本地Python不可用时使用环境提供的运行时，不安装新依赖；仍无法运行时按上面检查表人工检查，不能虚构脚本通过。
